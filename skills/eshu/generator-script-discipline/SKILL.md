# Generator script discipline

Scope: this is the `eshu` layer of the kit. Relative `docs/` paths and eshu repo tooling (`scripts/`, `specs/`, `make`, CI gates) resolve in the consuming repo checkout (see `skills/registry.md`).

A generator must produce identical bytes from identical inputs, keep its
committed output current, and fail visibly when the output contract is broken.
This applies to generators and their data registries, templates, tests, and CI
checks, including generators written outside shell.

Keep rendering code separate from substantial data or templates when that makes
changes clearer. A tiny
generator does not need empty library fragments to satisfy a prescribed layout.
Provide a test mirror that runs without Postgres, NornicDB, or a Go build.

## Proof and integration

1. **Test determinism and failure modes.** Test byte-for-byte idempotency
   (`cmp -s` is portable), required output shape, source-registry cross-links,
   and a meaningful negative case. Done when a clean re-run produces identical
   bytes and the negative case fails visibly:

   ```bash
   cp "${output_path}" "${output_path}.bak"
   bash "${generator_script}"
   cmp -s "${output_path}" "${output_path}.bak"
   ```

2. **Regenerate before final verification.** Regenerate changed artifacts before
   final verification, not after: a generated file committed after the local
   gates ran means they checked stale output. Include the regenerated bytes in
   the change and re-run to confirm no further drift. Done when a second run
   leaves `git status --short` clean.

3. **Avoid hand-edited ledgers on rebase.** Prefer a value derived from git or
   the tree on every run over a hand-edited ledger that a generator mirrors into
   committed output. A digest is a pure function of the tree, so two branches
   that touch the same row write different values and git cannot merge them; a
   clean textual merge of such a row is the dangerous case. The dirgate cap used
   to be one (`dirgate-grandfather.tsv` plus a generated Go mirror) and now
   derives its ratchet from git. If a ledger is unavoidable, never carry a
   resolved row forward across a rebase: take `origin/main`'s copy, re-derive
   the row for the current tree, regenerate the mirror, and never hand-edit the
   generated file. See
   `[fill-in: restack rule — this repo's restack and ledger-trap rule]`
   for the incident. Done when the generated mirror matches the re-derived tree.

4. **Wire blocking drift checks into CI.** For a release-blocking drift check,
   add the test and gate commands to
   `.github/workflows/static-contract-gates.yml` by default. Use a standalone
   workflow only for trigger, permission, or artifact-upload needs that the
   shared matrix cannot support. Read [CI integration](references/ci.md) for
   that exceptional workflow shape. Done when CI runs both the test mirror and
   the drift gate.

5. **Run the mirror and drift gate.** Run the affected generator's test mirror
   and drift gate. Add docs validation when documentation changes; preserve the
   repository's required gate floor. Done when every affected mirror and drift
   gate exits 0.

Read [test examples](references/testing.md) when implementing or extending a
mirror. For shell generators that render substantial template bodies, read
[shell portability](references/shell-portability.md) before choosing the output
mechanism. It records the Homebrew/Linuxbrew heredoc hang and the template-file
workaround; retain bounded watchdog tests for that failure mode.

Reference generated JSON in MkDocs prose when
it is not a documentation page; do not add a broken page link. Locale and
`jq` conventions live in [shell portability](references/shell-portability.md).
